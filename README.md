## task_1 — Рекомендация тарифов

**Задача.** Оператор «Мегалайн» хочет предлагать пользователям архивных тарифов один из
актуальных — «Смарт» или «Ультра». Нужна модель классификации с accuracy не ниже 0.75.

**Данные.** [`users_behavior.csv`](task_1/users_behavior.csv) — 3 214 записей о поведении
пользователя за месяц: `calls`, `minutes`, `messages`, `mb_used`, `is_ultra` (целевой признак).

**Что сделано.**
- EDA: гистограммы и описательные статистики в разрезе тарифов, матрицы корреляции.
- Масштабирование `StandardScaler`, балансировка классов через `SMOTE`
  (класс «Ультра» занимает ~30 % выборки).
- Проверка мультиколлинеарности через VIF и удаление признаков с корреляцией > 0.9
  (`calls` и `minutes` скоррелированы на 0.97).
- Разбиение на обучающую / валидационную / тестовую выборки, перебор гиперпараметров
  по сетке для трёх моделей.

**Результаты (accuracy валид. / тест).**

| Модель | valid | test |
|---|---|---|
| Random Forest | 0.843 | **0.841** |
| Decision Tree | 0.836 | 0.831 |
| Logistic Regression | 0.762 | 0.743 |

Порог 0.75 преодолён: лучший результат — Random Forest.

## task_2 — Определение стоимости автомобиля

**Задача.** Сервис по продаже подержанных авто строит модель для оценки рыночной
стоимости. Целевая метрика — RMSE не выше 2500. Обязательно проверить бустинги.

**Данные.** [`autos.csv`](task_2/autos.csv) — 354 369 анкет: тип кузова, год и месяц
регистрации, коробка передач, мощность, модель, пробег, тип топлива, марка, факт ремонта,
даты активности, `Price` — целевой признак.

**Что сделано.**
- Удаление неинформативных признаков (`DateCrawled`, `RegistrationMonth`,
  `NumberOfPictures`, `PostalCode`, `LastSeen`), приведение названий столбцов к snake_case.
- Обработка пропусков (`repaired` → 0/1, остальные категории → `unknown`), удаление дубликатов.
- Чистка аномалий: год регистрации позже даты объявления, фильтр 1970–2016;
  нормализация мощности (значения ≥ 10 000 л. с. делятся на 100) и фильтр 50–400 л. с.;
  обрезка цены по верхней границе IQR.
- Пайплайны `sklearn`: OHE + `StandardScaler` для линейных моделей,
  `OrdinalEncoder` для деревьев и бустингов; подбор гиперпараметров
  `GridSearchCV` / `RandomizedSearchCV`. Замер времени обучения и предсказания.

**Результаты (RMSE на кросс-валидации).**

| Модель | RMSE | time_fit | time_predict |
|---|---|---|---|
| LightGBM | **1305.12** | 59.4 s | 1.23 s |
| XGBoost | 1325.12 | 1 m 52 s | 743 ms |
| CatBoost | 1339.91 | 3 m 18 s | 738 ms |
| Decision Tree | 1540.48 | 46.7 s | 392 ms |
| Linear Regression | 2003.58 | 59 s | 574 ms |
| Ridge | 2008.24 | 1 m 52 s | 522 ms |

Финальная модель — LightGBM (`n_estimators=350`, `max_depth=5`, `learning_rate=0.1`):
**RMSE на тестовой выборке 1295.61**, что вдвое лучше требуемого порога.
Дополнительно построен график важности признаков.

## task_3 — Детектирование токсичных комментариев

**Задача.** Классифицировать комментарии на токсичные (1) и нетоксичные (0).
Целевая метрика — F1. Рассматриваются два подхода: классический TF-IDF и эмбеддинги
трансформера.

**Данные.** [`toxic_comments.csv`](task_3/toxic_comments.csv) — около 159 тыс.
англоязычных комментариев с разметкой `toxic`. Классы несбалансированы примерно 9:1.

**Что сделано.**
- EDA: распределение классов, длина комментариев по классам, топ-слова,
  би- и триграммы, облака слов.
- **Ветка TF-IDF (CPU):** лемматизация `WordNetLemmatizer` с определением части речи,
  очистка текста, удаление стоп-слов, `TfidfVectorizer`. Лемматизация всего корпуса
  занимает ~5 часов, поэтому результат сохранён в отдельный файл
  (ячейки предобработки закомментированы, ноутбук читает `test_preprocessed.csv`).
- **Ветка SentenceTransformer (GPU):** эмбеддинги `all-MiniLM-L6-v2` —
  3.5 минуты на GPU против ~2 часов на CPU.
- Модели: `LogisticRegression` и `CatBoostClassifier` на обоих типах признаков.
- Борьба с дисбалансом: `class_weight='balanced'`, DownSampling и подбор порога
  классификации по PR-кривой.

**Результаты (F1 на валидации).**

| Признаки | Модель | F1 (порог 0.5) | F1 (подобранный порог) |
|---|---|---|---|
| TF-IDF | Logistic Regression | 0.773 | **0.783** (порог 0.32) |
| TF-IDF | CatBoost | 0.756 | 0.769 (порог 0.31) |
| Embeddings | Logistic Regression | 0.703 | 0.730 (порог 0.30) |
| Embeddings | CatBoost | 0.701 | 0.724 (порог 0.34) |

Лучший результат — TF-IDF + логистическая регрессия со смещённым порогом.
Балансировка весов и DownSampling улучшили recall, но не F1; наиболее эффективным
способом учёта дисбаланса оказался подбор порога.

## task_4 — Обработка стали

**Задача.** Металлургический комбинат хочет снизить расход электроэнергии на этапе
обработки стали в ковше. Нужно предсказать итоговую температуру сплава.

**Данные.** Папка [`task_4/final_steel/`](task_4/final_steel/) — семь таблиц, связанных
по ключу партии `key`:

| Файл | Содержание | Строк |
|---|---|---|
| `data_arc.csv` | нагрев дугой: время начала/конца, активная и реактивная мощность | 14 876 |
| `data_bulk.csv` / `data_bulk_time.csv` | подача сыпучих материалов: объём и время | 3 129 |
| `data_gas.csv` | продувка газом | 3 239 |
| `data_temp.csv` | замеры температуры | 15 907 |
| `data_wire.csv` / `data_wire_time.csv` | подача проволочных материалов: объём и время | 3 081 |

**Что сделано.**
- Анализ каждого из семи датасетов по отдельности, визуализация пропусков (`missingno`).
- Формирование синтетических признаков и объединение таблиц по `key` в одну
  (2 329 партий, 18 признаков + целевой `final_temp`): стартовая температура,
  длительность обработки, активная/реактивная/полная мощность, время под током, газ,
  суммарные и отдельные объёмы сыпучих и проволочных материалов.
- Заполнение пропусков `KNNImputer`, анализ выбросов по IQR, проверка
  мультиколлинеарности и утечки целевого признака по матрице `phik`.
- Моделирование через `sktime`: разбиение `temporal_train_test_split` (75/25),
  масштабирование через `TabularToSeriesAdaptor`, рекурсивная редукция регрессоров
  (`make_reduction`). Метрики: MAE, RMSE, MAPE, sMAPE.

**Результаты на тестовой выборке.**

| Модель | MAE | RMSE | sMAPE |
|---|---|---|---|
| AutoARIMA | **6.26** | 76.93 | 0.393 |
| Linear Regression | 8.63 | 143.06 | 0.542 |
| CatBoost | 9.19 | 154.48 | 0.577 |
| Random Forest | 10.02 | 169.11 | 0.629 |
| Gradient Boosting | 10.08 | 172.07 | 0.633 |
| XGBoost | 10.21 | 176.02 | 0.641 |

Лучший результат показала AutoARIMA. Ноутбук завершается сравнением моделей —
итоговый раздел с выводами не оформлен.

## Стек

- **Работа с данными:** `pandas`, `numpy`
- **Визуализация:** `matplotlib`, `seaborn`, `plotly`, `missingno`, `wordcloud`
- **ML:** `scikit-learn`, `imbalanced-learn`, `statsmodels`, `phik`, `sktime`
- **Бустинги:** `lightgbm`, `catboost`, `xgboost`
- **NLP:** `nltk`, `pymystem3`, `sentence-transformers`, `tensorflow`

## Как запустить

```bash
python -m venv .venv
source .venv/bin/activate

pip install jupyter pandas numpy matplotlib seaborn plotly missingno \
            scikit-learn imbalanced-learn statsmodels phik sktime \
            lightgbm catboost xgboost \
            nltk pymystem3 sentence-transformers wordcloud tqdm

jupyter notebook
```

Ноутбуки читают CSV относительными путями, поэтому запускать их нужно
из каталога соответствующей задачи.

Замечания по отдельным проектам:
- **task_3** рассчитан на Google Colab с GPU (есть бейдж Colab в первой ячейке).
  Ячейки лемматизации закомментированы — ноутбук ожидает готовый файл
  `test_preprocessed.csv`, который в репозиторий не входит; чтобы получить его,
  нужно раскомментировать блок предобработки (~5 часов на CPU).
  Ветка SentenceTransformer требует GPU — на CPU кодирование занимает около 2 часов.
- **task_2** и **task_4** выполняются несколько минут: подбор гиперпараметров
  бустингов и `AutoARIMA` — самые долгие шаги.
